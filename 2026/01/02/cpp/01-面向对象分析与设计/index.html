# 第一部分 面向对象的基本概念

# 一、面向对象的复杂性

# 1.1 软件固有的复杂性

  1. 问题域的复杂性
  2. 管理过程的复杂性
  3. 软件中随处可能出现的灵活性
  4. 描述离散系统行为的问题

# 1.2 复杂系统的五个属性

  1. 层次结构
  2. 相对原本
  3. 分离关注：组件内部作用（高频率动作）和组件之间作用（低频率动作）的差异
  4. 共同模式：复杂系统具有共同的模式
  5. 稳定的中间形式

# 1.3 有组织和无组织的复杂性

# 1.3.1 复杂系统的规范形式

  1. 按一种完全正交的方式来分解这个系统
  2. “is a” 的层次结构
  3. 将系统的类结构和对象结构统称为系统的 “架构”

  1. 对象结构 ——“组成部分” 的层次关系；
  2. 类结构 ——” 是一种 “的层次关系
  3. 经验表明：最成功的复杂软件系统就是在设计中包含了深思熟虑的类结构和对象结构，并具备复杂属性的 5 中属性（层次结构、相对本原、分离关注、共同模式）

# 1.4 从混沌到有序

# 1.4.1 分解作用

  1. 算法分解
  2. 面向对象分解
  3. 算法分解与面向对象分解

# 1.4.2 分析和设计方法的分类

  1. 自顶向下的结构化设计
  2. 数据驱动设计
  3. 面向对象设计
  4. 结构化设计和面向对象设计无法同时使用，因为这两者的观点是正交的。开始分解系统时要么从算法开始，要么从对象开始，然后利用得到的结构作为框架来表达我们的看法。
  5. 经验使得我们首先使用面向对象的观点

# 1.4.2 抽象的作用

忽略复杂对象非本质的细节，转而处理这个对象的一般化的、理想化的模型

# 1.4.3 层次结构的作用

对象之间协作的交互模式

对象结构：展示了不同的对象之间如何通过一些交互模式进行写作

类结构：强调系统中的公共结构行为

# 1.5 复杂系统的设计

# 1.5.1 设计的含义

在软件工程中，设计的目的是要构建如下要一个系统：

构建一个系统的要求
  • 满足给定的（可能是非正式的）功能规格说明；
  • 符合目标介质的限制；
  • 满足隐含的和明确的性能及资源使用需求
  • 满足隐含的和明确的关于产品形式方面的设计限制条件
  • 满足对设计过程本身的限制条件，如时间、费用或进行设计可用的工具

设计的目的是 创建一个干净的、相对简单的内部结构，有时也被称为架构

# 1. 建模的重要性
  • 建模引证了分解、抽象和层次结构的原则
  • 尽量在旧模型上建立新模型
# 2. 软件设计方法学的要素

表达每个模型的语言

导致有序构建系统建模的过程

消除建模中的枯燥工作并强制是西安模型本身的规则的工件，可以揭示错误和不一致性

# 3. 面向对象开发的模型

构建关注问题域中的 “事物” 的模型具有很大的价值，这形成了我们所谓的面向对象分解。

面向对象分析和设计的方法实现了面向对象分解。通过应用面向对象设计，我们创建出能够灵活适应变化的软件，并体现出表达的经济性。通过明智地分离它的状态空间，我们对软件正确性的信心被提升到了一个新高度。最终，降低了开发复杂软件系统所固有的风险。

# 2.1 对象模型基础

# 2.1.1 面向对象编程

OOP 的定义 OOP 是一种实现的方法，在这种方法中，程序被组织成许多组相互协作的对象，每个对象代表，每个对象代表某个类的一个实例，而类则属于一个通过继承关系形成的层次结构。

  • 利用对象作为面向对象编程的基本逻辑构建块，而不是利用算法
  • 每个对象都是某个类的一个示例
  • 类与类之间可以通过继承关系联系在一起

如何确认该语言是面向对象的？

  1. 要支持对象，这些对象是具有命名的操作结构和隐藏内部状态的数据抽象
  2. 对象相关的类型为【类】
  3. 类型【类】可以从超类型【超类】中继承属性
